# A09

## Good
Updated files

### 1. Make some events
```bash
# Get a real JWT for amy
TOK_GOOD=$(curl -s -X POST http://localhost:8080/auth/login \
  -H 'content-type: application/json' \
  -d '{"email":"amy@example.com","password":"p@ssw0rd"}' | jq -r .token)

# Create two notes (idempotency key different so they’re unique)
curl -s -H "Authorization: Bearer $TOK_GOOD" \
  -H 'content-type: application/json' \
  -H 'Idempotency-Key: a09-1' \
  -d '{"title":"a09-one","body":"demo"}' \
  http://localhost:8080/notes | jq .

curl -s -H "Authorization: Bearer $TOK_GOOD" \
  'http://localhost:8080/notes?q=demo' | jq .

```
### 2. Review recent audit events

## Bad
### 1. No observability path
```bash
curl -i http://localhost:8081/admin/audit
```

## Takeaway
Without structured, centralized audit logs, you can’t detect or investigate abuse.
GOOD path:
Captures who did what, when, from where, with status and timing.
Sanitizes sensitive headers (no Authorization/cookies in logs).
Exposes a minimal, protected view (/admin/audit) for ops.
BAD path:
No audit trail → incidents are invisible or unanalyzable.
