# A06

## Good

```bash
TOK_GOOD=$(curl -s -X POST http://localhost:8080/auth/login \
  -H 'content-type: application/json' \
  -d '{"email":"amy@example.com","password":"p@ssw0rd"}' | jq -r .token)

curl -s -H "Authorization: Bearer $TOK_GOOD" \
  http://localhost:8080/admin/deps | jq 'map({path:.path, version:.version, min:.min, ok:.ok, replaced:.replaced})'
```

### Enforcement

```bash
ENFORCE_MIN_DEPS=1 go run ./cmd/api
# If anything is below your MinPolicy, GOOD server will exit with a fatal log.

```

## Bad
```bash
curl -i http://localhost:8081/admin/deps
# 404 Not Found
```

## Takeaway

Inventory matters: you can’t patch what you can’t see. The GOOD path exposes a minimal SBOM-lite view at runtime.
Policy gates: even a simple “min version” policy and optional fail-fast can catch risky drift (e.g., old JWT libs).
Replace detection: flagging **replace**d modules helps catch typosquatting/supply-chain surprises.
Where to go from here:
Run govulncheck ./... regularly (CI) and pin versions.
Keep GOSUMDB enabled; review go.sum diffs.
Generate a real SBOM (CycloneDX/Syft) if you want a richer inventor
